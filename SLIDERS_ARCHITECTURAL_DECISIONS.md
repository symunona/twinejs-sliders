## Three bugs integration caught

Worth calling out because none showed up in unit tests:

**1. `y` defaulted to 0, which is mid-air.** The schema materialized a bare `at: -0.4` as
`{x: -0.4, y: 0}`, while the renderer (correctly, per spec) maps `y: 0` to the *centre* of
the stage. Characters therefore stood in mid-air with their heads cropped off the top. The
spec says an omitted y means "the layer's baseline" — which is the floor, not zero. Fixed
with a shared `LAYER_BASELINE` constant (−0.85: a character is ~0.9 of stage height with
its origin at its feet, so this puts the head just inside the top edge).

**2. Closing the character editor discarded the last edit.** Saves are debounced 400 ms,
and the debounce's cleanup *cancelled* the pending write on unmount. Renaming a frame and
immediately closing the dialog lost the rename — which is exactly what a person does. Now
flushes on unmount, writing through the store directly so it doesn't setState after
unmount.

**3. A bare `[[stay]]` made Twine invent a passage called "stay".** Twine's own editor
parses `[[…]]` out of the passage *source* to draw the map and auto-create passages, so the
target has to be inline: `[[stay -> Tavern - Fight]]`. The `links:` map now carries only
presentation props, and the parser fills a missing `to:` from the inline link instead of
erroring.

## Sub-agent decisions worth knowing

Full reasoning is in each package; the ones that could surprise you:

- **`at: -0.4` materializes as `{x: -0.4, y: LAYER_BASELINE}`** — `Vec2` requires both fields, so "y omitted" has to become a concrete value; see bug 1 above for why that value is the baseline and not 0.
- **Nested flow collections are allowed**, contradicting spec 05 — because spec 02's own example (`candle: {at: [0.1, -0.2], layer: front}`) uses one.
- **`fx:` in a patch replaces wholesale** (so `fx: []` clears); `camera:` merges per-field.
- **A beat patching an absent entity is ignored**, not auto-created — there's no "enter" beat, so that case is a typo.
- **Cycles in `from:`** report one error per scene and still compile from an empty base, so the preview keeps rendering.
- **Prop scale** reads pixel size against a 1080-tall design stage; the character rule (`size.h → 0.9` of stage) would make a candle 90% of the screen.
- **`measure()` returns the target position, not the animating one** — deterministic and testable; bubbles glide via their own CSS transition.
- **Anchors fall back to defaults** when a character manifest is missing, so a bubble on an unresolved speaker is still placed rather than dropped.

## Not built

- **Visual editor (spec 07)** — drag-on-preview write-back. Everything it needs is in place (`yaml` round-trip, `measure()`, stable DOM hooks); it's the next piece. Build plan: [`docs/sliders/09-visual-editor-plan.md`](docs/sliders/09-visual-editor-plan.md).
- **Electron asset backend** — interface + stub only. Web (OPFS/IndexedDB) is live.

## How to run it

```sh
# hosted build (already running on the tailnet)
./scripts/serve-sliders.sh 8817        # http://100.81.125.107:8817/

# dev server with hot reload
npx vite --host 0.0.0.0 --port 5173

# tests
npx jest                               # 2053 unit tests
npx playwright test                    # 15 E2E, real browser

# rebuild the story format after changing packages/scene-*
# SLIDERS_PACKAGES is required: the format's alias resolver looks for
# ../twinejs-sliders/packages, which is not where this repo lives, and it THROWS
# rather than falling back to stubs.
cd /mnt/data_ssd/dev/sliders-format
export SLIDERS_PACKAGES=/mnt/data_ssd/dev/twinery/twine-sliders-2/packages
npm run build:format && npm run verify
cp dist/use/0.1.0/format.js \
   /mnt/data_ssd/dev/twinery/twine-sliders-2/public/story-formats/sliders-0.1.0/format.js
```

The format bundles `packages/scene-*`, so **changing a scene package means rebuilding the
format**, not just the editor.
